## Turn 130: Assistant

Here is the full breakdown of why **`antd`** is an issue and the options available:

---

### 1. Why `antd` was there
- [`hooks/use-pagination.ts`](file:///D:/work/qcash-ui-announcement-management/hooks/use-pagination.ts) was originally copied during the initial migration from the monolith repo (`first init move from monolith`).
- In the monolith repo, `antd` was installed, but in this micro-frontend repository, **`antd` was never added to `package.json`**.
- TypeScript strict checking during CI/CD (`RUN yarn build`) strictly fails the build:
  ```text
  ./hooks/use-pagination.ts:2:25
  Type error: Cannot find module 'antd' or its corresponding type declarations.
    1 | import type { MapDataFn, QueryParams, ServiceDataFn, SortType } from "@/types";
  > 2 | import { message } from "antd";
  ```

---

### 2. Available Options

| Option | Action | Pros | Cons |
| :--- | :--- | :--- | :--- |
| **Option A (Current / Recommended)** | Remove `antd` import and use `console.error` (with `defaultSetError` callback intact) | • Stays lightweight<br>• Zero unused bundle overhead<br>• Build passes immediately | Uses browser/server console for unhandled pagination errors instead of an antd toast |
| **Option B (Install `antd`)** | Add `"antd": "^5.x"` to `package.json` | • Satisfies reviewer literally without changing the code | • Pulls a massive 50MB+ dependency and styling bloat into a micro-frontend just for 1 line of fallback error |
| **Option C (Local Toast/Fallback Shim)** | Provide a lightweight fallback / custom toast if UI message popup is strictly required | • Build passes<br>• Keeps bundle lightweight | Requires custom wrapper |

---

### Recommendation
**Option A** is the industry standard for Micro-Frontends (MFE), as QCash UI uses its own UI components (`@bri/addons-auth-provider`, Tailwind, custom modals/messages) and does not use Ant Design.
