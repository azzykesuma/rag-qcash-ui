## Turn 42: Assistant

Error **`You are passing a wrong module! Please check the object you are passing to i18next.use()`** saat prerendering Next.js (`next build`) terjadi karena adanya **ketidakcocokan versi (version mismatch) dan perubahan format modul (ESM/CJS interop)** setelah `yarn.lock` dihapus dan di-install ulang.

Berikut analisa lengkap penyebab dan solusinya:

---

### 1. Akar Penyebab Masalah

#### A. Transitive Dependency ter-upgrade ke versi yang incompatible
Di dalam [package.json](file:///D:/work/qcash-ui-account-statement/package.json), library internationalization yang digunakan adalah:
* `"ni18n": "^1.1.0"`
* `"i18next": "^22.5.0"`
* `"react-i18next": "^15.0.2"`

Ketika `yarn.lock` dihapus lalu dijalankan `yarn install` baru:
1. `ni18n` membawa sub-dependency (transitive dependencies) berupa `"i18next-fs-backend": "^2.1.1"` dan `"i18next-http-backend": "^2.2.0"`.
2. Karena tanda caret (`^`), yarn mengambil versi terbaru yang tersedia di registry (seperti `i18next-fs-backend@2.3.x` / `2.5.x`).
3. Versi baru dari `i18next-fs-backend` / `i18next-http-backend` telah mengubah struktur packaging menjadi modern ESM (`"type": "module"`).
4. Ketika Next.js melakukan bundling & prerendering SSR/SSG untuk halaman statis (`/`, `/500`, `/view/[id]`), helper loader `ni18n` mencoba me-load backend tersebut dan mengirimkannya ke `i18next.use()`:
   ```javascript
   // Di dalam use-backend ni18n:
   i18n.use(i18next_fs_backend_1.default);
   ```
5. Karena format module export berubah, objek yang diterima bukanlah instance/class plugin yang memiliki properti `type: "backend"`, melainkan objek wrapper (misal `{ default: ... }` atau `undefined`).

#### B. Pengecekan Strict di `i18next`
Di dalam implementasi `i18next`:
```javascript
use(module) {
  if (!module) throw new Error('You are passing an undefined module! ...');
  if (!module.type) throw new Error('You are passing a wrong module! Please check the object you are passing to i18next.use()');
  // ...
}
```
Karena `module.type` bernilai `undefined`, error `You are passing a wrong module!` langsung dilempar dan menggagalkan proses *static page generation*.

#### C. Versi `react-i18next` Mismatch
Di repositori ini [package.json](file:///D:/work/qcash-ui-account-statement/package.json), `react-i18next` diset ke `^15.0.2`. Padahal:
- Standar Micro-Frontend (MFE) QCash lain (seperti `qcash-ui-account-summary`, `qcash-ui-dashboard`, dll) menggunakan `react-i18next@^12.3.1` bersama dengan `ni18n@^1.1.0` & `i18next@^22.5.0`.
- `react-i18next` v15 mensyaratkan `i18next >= 23.2.3` (peer dependency mismatch dengan `i18next@22.5.0`).

---

### 2. Kenapa Tidak Disarankan Menghapus `yarn.lock` di Ekosistem MFE?

`yarn.lock` berfungsi mengunci seluruh pohon dependensi (*dependency tree*) termasuk ratusan sub-dependency yang tidak tertulis langsung di `package.json`. 

Ketika `yarn.lock` dihapus:
* Dependency yang memakai tanda `^` atau `~` akan meloncat ke rilis patch/minor terbaru di npm.
* Rilis-rilis baru sering membawa perubahan internal (misal migrasi CJS ke ESM, perubahan bundling Webpack) yang bisa merusak kompatibilitas Webpack 5 Module Federation dan Next.js 13.

---

### 3. Solusi / Cara Memperbaiki

#### Rekomendasi 1: Kembalikan `yarn.lock` Asli (Paling Aman)
Jika tidak ada kebutuhan khusus untuk memperbarui dependency:
1. Kembalikan file `yarn.lock` dari git:
   ```powershell
   git checkout HEAD -- yarn.lock
   ```
2. Jalankan install ulang sesuai lockfile:
   ```powershell
   yarn install --frozen-lockfile
   ```

## Turn 53: Assistant

Kasus ini sering terjadi ketika ada **re-publish package dengan versi yang sama** ke Nexus (*mutable package release*). 

Ketika hash tarball di Nexus berubah, `yarn.lock` lama akan menolak instalasi di Bamboo (CI/CD) karena **Integrity Check Failed (SHA Mismatch)**. Namun, jika seluruh `yarn.lock` dihapus, Anda berisiko memicu breaking change dari ratusan sub-dependency lain yang ikut ter-upgrade.

Berikut beberapa cara mitigasi yang tepat dan aman tanpa perlu menghapus seluruh `yarn.lock`:

---

### 1. Update Spesifik Package Tersebut Saja di `yarn.lock` (Disarankan)

Jangan hapus seluruh `yarn.lock`, melainkan perbarui **hanya entry package tersebut**:

#### Cara A: Gunakan `yarn upgrade`
Jalankan perintah upgrade hanya untuk package yang bersangkutan:
```powershell
yarn upgrade @ordentco/addons-auth-provider
```
*(Atau sesuaikan nama package-nya, misal `@bri/addons-auth-provider`)*

Perintah ini hanya akan memperbarui URL, versi, dan checksum `integrity: sha512-...` milik package tersebut di [yarn.lock](file:///D:/work/qcash-ui-account-statement/yarn.lock), sedangkan dependency lainnya tetap terkunci rapat.

#### Cara B: Hapus Entry Package Tertentu di `yarn.lock`
1. Buka [yarn.lock](file:///D:/work/qcash-ui-account-statement/yarn.lock) di text editor.
2. Cari blok yang berkaitan dengan package tersebut, contoh:
   ```yaml
   "@ordentco/addons-auth-provider@0.9.119-mfe":
     version "0.9.119-mfe"
     resolved "https://nexus.../addons-auth-provider-0.9.119-mfe.tgz#..."
     integrity sha512-...
   ```
3. Hapus seluruh blok tersebut saja.
4. Bersihkan cache lokal package tersebut dan install ulang:
   ```powershell
   yarn cache clean @ordentco/addons-auth-provider
   yarn install
   ```
5. Yarn hanya akan membuat ulang checksum baru untuk package tersebut dan mempertahankan sisa file `yarn.lock`.

---

### 2. Bersihkan Local Yarn Cache

Karena Yarn me-cache file `.tgz` berdasarkan nomor versi di local machine:
```powershell
yarn cache clean @ordentco/addons-auth-provider
```
Jika tidak dibersihkan, Yarn di local Anda mungkin masih menggunakan tarball lama dari cache lokal dan tidak mengambil tarball baru dari Nexus.

---

### 3. Solusi Jangka Panjang: Gunakan Pre-release / Patch Tag

Meng-overwrite package pada versi yang sama di artifact registry (Nexus) adalah anti-pattern yang sering menimbulkan *cache poisoning* baik di mesin developer maupun di runner Bamboo.

Jika memungkinkan, lebih baik menggunakan penomoran versi baru meskipun minor:
* Contoh: `0.9.119-mfe.1`, `0.9.119-mfe-fix`, atau naik ke `0.9.120-mfe`.
* Dengan menaikkan versi (walau hanya patch/build metadata), Anda cukup mengubah angka versi di [package.json](file:///D:/work/qcash-ui-account-statement/package.json) dan menjalankan `yarn install`, sehingga integritas hash dan cache tidak akan pernah konflik.
