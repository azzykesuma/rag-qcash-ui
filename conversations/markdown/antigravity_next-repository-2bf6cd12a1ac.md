There are two main reasons why some console logs show the data while others return `undefined`:

---

### 1. Property Name Mismatch: `productAuthority` vs `productAuthorities` (Primary Reason)

In `@bri/addons-auth-provider`, `useAuth()` returns **`productAuthorities` (plural)**.

* **Where it worked (correctly fetched):**
  * **`qcash-ui-bank-monitoring-transaction`**: Destructured `productAuthorities` (plural) &rarr; `console.log(productAuthorities?.TEST_PRODUCT)` ✅
  * **`qcash-ui-plafon-pegadaian`**: Destructured `productAuthorities` (plural) &rarr; `console.log(productAuthorities?.TEST_PRODUCT)` ✅

* **Where it stayed `undefined`:**
  * **`qcash-ui-dashboard`**: Destructured `productAuthority` (singular) &rarr; `console.log(productAuthority?.TEST_PRODUCT)` ❌ (`productAuthority` does not exist on `useAuth()`)
  * **`qcash-ui-beneficiary-account-management`**: Destructured `productAuthority` (singular) &rarr; `console.log(productAuthority?.TEST_PRODUCT)` ❌

---

### 2. Async Lifecycle & Initial Render Timing

When a page initially mounts, `useAuth()` starts in an initial state (`isAuthoritiesReady: false` / empty initial authorities) while it asynchronously validates the token and queries user authorities (`guard()`):

1. **1st Render (Initial Mount)**: `isAuthoritiesReady` is `false` &rarr; logs `undefined` (or default placeholder).
2. **2nd Render (After Auth API resolves)**: `isAuthoritiesReady` becomes `true`, state updates, component re-renders &rarr; logs the actual populated authority object (if using `productAuthorities`).
