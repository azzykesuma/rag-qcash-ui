## Turn 200: Assistant

Hasil investigasi terhadap repositori [**`addons-auth-service`**](https://internal-service.example.com/projects/ADDONS/repos/addons-auth-service/browse), alur frontend di [**`qcash-ui-landing-page`**](file:///D:/work/qcash-ui-landing-page), serta service autentikasi downstream (`qcash-sso-service`, `minerva`, dan `trevenant`):

---

### 1. Ringkasan Temuan: Dari Mana Error `OTP01` Berasal?

Error:
```json
{
    "statusCode": "OTP01",
    "statusText": "gagal",
    "message": "invalid otp"
}
```

* **Bukan berasal dari `addons-auth-service`**:
  `addons-auth-service` hanya menangani autentikasi kredensial tingkat pertama (username, password, session cookies, dan OTP via Email). Di seluruh proto maupun Go codebase `addons-auth-service`, tidak ada logika validasi soft token/hard token MFA ataupun kode error `OTP01`.
* **Asal Error Sebenarnya**:
  Setelah kredensial username & password lolos di tahap pertama, frontend (`login2fa-modal.tsx`) memanggil endpoint validasi MFA token (`/auth/mfa/token/validate` atau `/verification-sso/ibbiz/validate-token`). Request ini diteruskan oleh SSO gateway (`qcash-sso-service` / `vanillite`) ke service token downstream: **`minerva`** (atau `trevenant` / Gemalto / Entrust IdentityGuard).
  Di service **`minerva`** (`src/otp/consts.go`):
  ```go
  ErrInvalidOTP = response.ErrorStruct{Code: "OTP01", Description: "failed", Message: "invalid otp"}
  ```
  Ketika OTP yang dimasukkan tidak cocok dengan hasil kalkulasi seed/counter token di server, service tersebut me-return HTTP 400 dengan payload `statusCode: "OTP01"`.

---

### 2. Mengapa Token `CMSBRI_QA2` Gagal, Sedangkan Token Lain Berhasil?

Token `CMSBRI_QA2` adalah identitas/profil soft token di aplikasi **Entrust Identity / BRI Soft Token**. Kegagalan spesifik pada profil ini (sementara profil token lain bekerja normal) disebabkan oleh salah satu dari 3 kemungkinan utama berikut:

#### A. Ketidaksesuaian Environment Server Token (Paling Sering Terjadi)
* Profil `CMSBRI_QA2` didaftarkan/di-provisioning pada backend **Entrust / Minerva environment QA2**.
* Sementara itu, environment QCash backend tempat Anda melakukan login saat ini (misal: DEV, SIT, atau QA1) dikonfigurasi mengarah ke backend token server **QA1 / DEV** (`MINERVA_BASE_URL` atau `BRIGATE_GEMALTO_URL` yang berbeda).
* **Dampak**: Server token yang dihubungi oleh backend QCash tidak mengenali seed / secret key dari profil `CMSBRI_QA2`, sehingga validasi OTP selalu menghasilkan `OTP01` (*invalid otp*). Sebaliknya, profil token lain yang berhasil kemungkinan memang di-generate dari server QA1/DEV yang sesuai.

#### B. User-to-Token Binding Mismatch (Pemetaan Serial Token ke User)
* Pada sistem User Management (`cerberus` / `griffin` / `gryphon` / QCash User Management), setiap user login di-bind ke satu **Nomor Seri Token (Token Serial ID)** tertentu.
* Jika user yang sedang Anda pakai untuk login di-assign ke serial token A, tetapi Anda memasukkan 6-digit OTP dari profil `CMSBRI_QA2` (yang terikat pada user/serial lain), maka server akan menghitung OTP berdasarkan serial milik user tersebut dan mendeteksi OTP Anda tidak cocok (`OTP01`).

#### C. Time Drift / Counter Desynchronization (Desinkronisasi Waktu / Counter)
* Soft token berbasis waktu (TOTP) atau event/counter (HOTP).
* Jika jam perangkat HP/PC tempat aplikasi token `CMSBRI_QA2` berjalan selisih beberapa puluh detik/menit dengan server, atau jika counter internal token di server tertinggal akibat OTP ditekan berulang kali tanpa di-submit, server akan menolak OTP tersebut.

---

### 3. Langkah Rekomendasi untuk Memperbaiki

1. **Cek Mapping Token User di Admin Portal / Database**:
   * Periksa di User Management (BO / Admin BRICaMS / QCash) user ID yang Anda gunakan login: pastikan serial token yang terpasang pada user tersebut memang benar serial dari profil `CMSBRI_QA2`, bukan serial token lain.
2. **Cek Target Server Profil Token di Entrust**:
   * Cek saat scan QR / aktivasi soft token `CMSBRI_QA2`, server URL yang dimasukkan mengarah ke QA2 atau QA1. Samakan dengan target environment QCash yang sedang diuji.
3. **Lakukan Token Resynchronization (Resync)**:
   * Jika masalahnya adalah time/counter drift, lakukan sinkronisasi token melalui menu Admin/Helpdesk Token atau submit 2 OTP berturut-turut jika sistem mendukung sinkronisasi counter.
4. **Verifikasi Waktu Perangkat**:
   * Pastikan jam pada smartphone/aplikasi soft token diatur ke **Automatic / Network-provided time**.

## Turn 258: Assistant

Untuk melakukan validasi data token dan penyebab error `"invalid otp"` (`OTP01`), tabel utama yang menyimpan data pendaftaran dan seed soft token di backend BRI/IBBIZ adalah:

---

### 1. Tabel Utama: `st_user` (Database Soft Token / Uranus)

Tabel ini berada di database service **Soft Token** (service `uranus` / `softtoken`). Tabel ini menyimpan binding antara identitas user, device, application ID, dan seed enkripsi OTP.

#### Kolom Kunci yang Perlu Dicek:
| Kolom | Tipe | Keterangan & Kondisi Normal |
| :--- | :--- | :--- |
| **`username`** | `varchar` | Username / Client Handle (misal: user terkait `CMSBRI_QA2`). |
| **`activation_status`** | `tinyint` / `int` | **Harus `1`** (Active). Jika `0`, token belum diaktivasi atau sudah dinonaktifkan. |
| **`user_status`** | `tinyint` / `int` | **Harus `1`** (Active). |
| **`application_id_new`** | `varchar` | ID aplikasi mobile Soft Token yang aktif. Tidak boleh kosong/null. |
| **`seed_encrypt_new`** | `text` / `varchar` | Seed kunci enkripsi untuk kalkulasi OTP. Jika null atau tidak sesuai dengan seed di app pembuat OTP, verifikasi akan gagal. |
| **`device`** | `varchar` | Perangkat/HP yang terdaftar untuk token tersebut. |
| **`activation_time`** | `datetime` | Tanggal/waktu aktivasi token. |

#### Contoh Query Validasi:
```sql
SELECT 
    username, 
    service, 
    device, 
    activation_status, 
    user_status, 
    application_id_new, 
    activation_time, 
    modified_time
FROM st_user 
WHERE username = '<username_atau_token_id>';
```

> **Kemungkinan Penyebab di `st_user`:**
> 1. `activation_status` bernilai `0` (Inaktif).
> 2. `application_id_new` berbeda dengan ID aplikasi mobile yang saat ini Anda gunakan untuk generate OTP.
> 3. Seed `seed_encrypt_new` ter-reset atau tidak sinkron (misal aplikasi di HP pernah di-reinstall tanpa aktivasi ulang).

---

### 2. Tabel Mapping Pengguna & Token (Database User Management / Griffin)

Di level user management (BRICaMS / IBBIZ Core DB):
- **Tabel**: `users` atau `client_users` / `user_tokens`
- **Field yang dicek**:
  - `token_type`: Pastikan tipenya `SOFT_TOKEN` (bukan `HARD_TOKEN`).
  - `token_serial` / `token_id`: Pastikan ter-assign ke serial/handle yang benar (`CMSBRI_QA2`).
  - `status`: Pastikan status token `ACTIVE` (tidak terblokir karena salah input OTP $\ge 3$ kali berturut-turut).

---

### 3. Alternatif: Entrust IdentityGuard Console (Jika Menggunakan Token Server Eksternal)

Jika environment QA diarahkan ke server Entrust IdentityGuard / Gemalto:
- Seed dan status token disimpan di direktori LDAP / DB Entrust (bukan di SQL table lokal).
- Pengecekan dilakukan via **Entrust IdentityGuard Admin Console**:
  - Cari user/token: `CMSBRI_QA2`.
  - Cek status token: apakah berstatus **Active**, **Locked** (terkunci), atau butuh **Resynchronize** (time drift/counter clock pada generator OTP tergeser).
