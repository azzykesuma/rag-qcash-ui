## Audit result

Research-only review completed. No files were changed.

Scope included the five requested root guides, `ARCHITECTURE.md` because all workflow documents depend on it, four root Claude agents, the workflow coverage agent, and all eight nested `AGENTS.md` files.

Overall, the guidance is **not reliable as a single current workflow**. It mixes:

## Highest-priority findings

### 1. No defined precedence between duplicate FE and QA role cards

- `~/Development/KNOWLEDGE.md:12-16` instructs agents to read both `AGENT-SFE.md`/`AGENT-QA.md` and the active `.claude/agents/` definitions.
- `~/Development/AGENT-SFE.md:90-100` mandates test-first development, a logger call for every change, Jest, and a real `persist-logger`.
- `~/Development/.claude/agents/fe.md:20-26` instead requires implementation and available verification, without those universal requirements.
- `~/Development/AGENT-QA.md:10-16` says QA writes unit tests and reports only to PM; only PM approves.
- `~/Development/.claude/agents/qa.md:12-30` says QA derives/runs tests, reports PASS/FAIL, and sends failures directly to FE.
- `~/Development/DEV-FLOW.md:25` agrees with the active QA agent, not the old QA card.

**Correction:** Declare `.claude/agents/*.md` authoritative and either retire the root role cards or label them explicitly as historical/session-auth supplements. Assign test ownership unambiguously: FE writes/updates automated tests; QA reviews, executes, live-verifies, and signs off.

## Missing roles and workflow gates

### Missing backend implementation role

- PM is expected to identify backend impact at `~/Development/.claude/agents/pm.md:13-18`.
- The only implementation role is frontend: `~/Development/.claude/agents/fe.md:2-3`.
- `~/Development/DEV-FLOW.md:14-25` has no backend/security lane despite auth work involving `addons-auth-service`.

**Addition:** Add a backend agent or explicitly route backend changes to a human/backend team before FE completion.

### Missing instruction-discovery gate

Active agents read `ARCHITECTURE.md`, README, and CLAUDE files, but not the nearest `AGENTS.md`:

- `~/Development/.claude/agents/pm.md:10-12`
- `~/Development/.claude/agents/fe.md:10-12`
- `~/Development/.claude/agents/qa.md:9-10`

That omission would miss Bun/pnpm, Next 16, Biome, and repo-specific test-layout rules found in this audit.

**Addition:** Before planning or editing, require discovery of all applicable instructions from workspace root to target directory, with nearest-file precedence.

### Missing UI-library selection gate

- `~/Development/.claude/agents/ui-ux.md:11-16` and `~/Development/.claude/agents/fe.md:18` universally require `qcash-global-component`.
- Current repositories can instead use the `qui` remote, e.g. `~/Development/qcash-ui-dashboard-auto-collection/next.config.ts:35-46`.

**Addition:** Add a per-repo gate choosing legacy `qcash-global-component`, QUI, or local UI components. Do not mandate one globally.

### Missing security/privacy gate

The workflow has an architecture gate but no explicit security review for token storage, MFA, request signing, redirect validation, or logging credentials.

**Addition:** Require security review for auth/session/header/storage changes, including no secrets or passwords in evidence/logs and validation of saved redirect paths.

### Incomplete shared-package release gate

- `~/Development/DEV-FLOW.md:31,41-42` requires a published version bump but reserves publishing for humans.
- There is no gate requiring consumer manifest/lockfile updates, build artifact verification, compatibility testing, or rollback instructions.

**Addition:** Add: source package tests → build artifact → approved publish → consumer version/lock update → host+remote integration verification → rollback/version record.

### No freshness/branch applicability gate for guidance

`TEST-CASES.md` is branch-specific, while architecture and knowledge documents have static dates and copied package versions.

**Addition:** Every root guide should state authoritative branch/commit, applicability, owner, and last-verified date. Prefer links to manifests/code over duplicated volatile values.
