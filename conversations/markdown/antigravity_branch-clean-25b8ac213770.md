#### 2. Why Was It Changed? (Intent)
In the older code:
- `getSortValue.ts` was a flat, global mapping with hacky ternary functions (e.g. `company_id: (activeTabs) => activeTabs === "non-deposito" ? ... : ...`).
- Deposito download had an actual bug where it mapped its sort via `getSortValue(getSort, "non-deposito")`.
- `getColumnAccessor` had no concept of tabs, causing visual sort header mismatches when multiple tabs shared backend keys.
- The RDN table had over 100 lines of duplicated inline sorting logic in [containers/index.tsx](file:///C:/Work/qcash-ui-account-management/containers/index.tsx).

The refactoring unified all 4 tabs under a single contract (`TAB_SORT_CONFIG`) with explicit forward and reverse resolvers, documented in [docs/2026-09-account-index-refactor.md](file:///C:/Work/qcash-ui-account-management/docs/2026-09-account-index-refactor.md).

---

#### 3. Crash Risk Analysis

1. **No Dangling Internal References**:
   - Zero occurrences of `getSortValue`, `getColumnAccessor`, or `sortingMappings` remain in the code (verified via git grep).
   - All call sites in [containers/index.tsx](file:///C:/Work/qcash-ui-account-management/containers/index.tsx), [services/index.ts](file:///C:/Work/qcash-ui-account-management/services/index.ts), and test files were updated to use `resolveBackendSortKey` / `resolveColumnAccessor`.
2. **Safe Fallbacks**:
   - `resolveBackendSortKey` returns `undefined` on unsortable/unknown columns, which triggers `restoreDefault()` in `containers/index.tsx`.
   - `resolveColumnAccessor` falls back to the backend key itself if no reverse mapping exists (`?? backendKey`).
   - `services/index.ts` uses `resolveBackendSortKey(...) ?? getSort`, so downloads never receive `undefined`.
3. **Module Federation Safety**:
   - Checked [next.config.js](file:///C:/Work/qcash-ui-account-management/next.config.js#L11-L21): `qcash-ui-account-management` **only exposes Next.js Page routes** (`./account`, `./add`, `./single`, `./multiple`, `./edit`, `./view`, etc.) and `./globals` CSS.
   - It **does not expose** any internal utilities or constants.
   - In the host container (`qcash-ui`), it only dynamically loads the page components (e.g., `loadRemote("qcash-ui-account-management/account")`). External consumers are completely isolated from internal helper renames.
4. **Stability Improvements Added in This PR**:
   - Added `AbortController` in [hooks/use-pagination.ts](file:///C:/Work/qcash-ui-account-management/hooks/use-pagination.ts) and [`isRequestCancelled`](file:///C:/Work/qcash-ui-account-management/utils/errors.ts) to abort pending table requests upon tab switching, preventing race conditions and false "Internal Server Error" modals.
