### Executive Summary

The blank white screen on the second tab occurs because the host application (`qcash-ui`) currently deployed on the preploy environment has an active `storage` event listener in [`HostAuthGate.tsx`](file:///C:/Work/qcash-ui/components/providers/HostAuthGate.tsx). 

When Tab 1 logs out from Header-Footer, it deletes `access-token` from `localStorage`. Tab 2 detects this deletion via the `storage` event, resets its internal auth state, and immediately renders `return null;` (unmounting Header, Footer, and the Issuance LC form). Because the `useEffect` dependencies do not trigger, Tab 2 **never initiates a redirect** and remains frozen on a blank white screen indefinitely.

---

### Step-by-Step Root Cause Analysis

```mermaid
sequenceDiagram
    autonumber
    actor User
    participant Tab1 as Tab 1 (Active Logout)
    participant Storage as Browser localStorage
    participant Tab2 as Tab 2 (Idle Tab)
    participant Gate as HostAuthGate (Tab 2)

    User->>Tab1: Click "Logout" in Header-Footer
    Tab1->>Storage: removeItem("access-token")
    Tab1->>Tab1: router.push("/landing-page")
    Storage-->>Tab2: window.dispatchEvent("storage", { key: "access-token", newValue: null })
    Tab2->>Gate: handleStorage() fires -> resetHostAuthValidation()
    Gate->>Gate: hasMountedRef = false, setIsValidated(false)
    Note over Gate: Re-renders with token=null & isHostValidated=false
    Gate-->>Tab2: return null; (Unmounts all children -> Blank Screen)
    Note over Gate: useEffect dependencies didn't change -> Redirect never runs!
```

#### 1. What happens on Tab 1 (Header-Footer Logout)
In [`qcash-ui-header-footer`](file:///C:/Work/qcash-ui-header-footer/layouts/default/container/header/components/ListItem.tsx#L55-L68):
- Clicking **Logout** in Header-Footer triggers `_logout(destination)`.
- It invokes `logout()` from `@bri/addons-auth-provider`, which removes `access-token`, `refresh-token`, `login`, `productMenu`, and `validateMenu` from `localStorage`, clears session cookies, and pushes Tab 1 to `/landing-page`.

#### 2. What happens on Tab 2 (The Inactive Tab)
- When `localStorage.removeItem("access-token")` executes in Tab 1, the browser broadcasts a native `storage` event across all other tabs sharing the same origin:
  ```ts
  // components/providers/HostAuthGate.tsx (preploy bundle)
  const handleStorage = (event: StorageEvent) => {
    if (event.key === "access-token" && event.newValue === null) {
      resetHostAuthValidation();
    }
  };
  window.addEventListener("storage", handleStorage);
  ```
- `resetHostAuthValidation()` immediately resets the gate state:
  ```ts
  hasMountedRef.current = false;
  setIsValidated(false);
  setHostAuthGuardState({ token: null, status: "idle" });
  ```
- `setIsValidated(false)` triggers a React re-render of `HostAuthGate`. During this render:
  ```ts
  const token = getAccessToken(); // null
  const guardState = readHostAuthGuardState();
  const isHostValidated = isValidated && guardState.token === token && guardState.status === "validated"; // false

  if (!token || !isHostValidated || !briAuth.isAuthoritiesReady || !hasMountedRef.current) {
    return null; // <--- Returns null immediately!
  }
  ```
  `HostAuthGate` returns **`null`**, completely tearing down the entire DOM tree (Header-Footer layout and `qcash-ui-issuance-lc` MFE).

#### 3. Why Tab 2 Never Redirects (The Deadlock)
The redirection logic in [`HostAuthGate.tsx`](file:///C:/Work/qcash-ui/components/providers/HostAuthGate.tsx#L199-L210) resides in a `useEffect`:
```ts
if (!token) {
  if (!redirectingRef.current) {
    redirectingRef.current = true;
    router.replace("/landing-page");
  }
  return;
}
```
However, the `useEffect` dependency array is:
```ts
[authError, currentPath, briAuth.token, briAuth.isAuthoritiesReady, publicRoute, router, router.isReady]
```
- `briAuth.token` in React context memory was not updated because `@bri/addons-auth-provider` does not listen to `storage` events (it still holds the old token string).
- `isValidated` and `hasMountedRef` are not in the dependency array.
- None of the declared dependencies changed, so **`useEffect` never executes**.
- Tab 2 stays stuck returning `null` forever.

### Why This Happened in Preploy

Inspection of the git commit history in `qcash-ui` reveals that this issue was already addressed on `dev` in commit [`9c90eb49`](file:///C:/Work/qcash-ui/components/providers/HostAuthGate.tsx):
- **Commit:** `9c90eb49393cffe1e774913b0eb8e039f126e123` (*"fixing blank screen on token deleted"*).
- **Changes in that fix:**
  1. Removed `window.addEventListener("storage", handleStorage)`.
  2. Guarded against unmounting mounted pages:
     ```diff
     - if (!token || !isHostValidated || !briAuth.isAuthoritiesReady || !hasMountedRef.current) {
     + if (!hasMountedRef.current && (!token || !isHostValidated || !briAuth.isAuthoritiesReady)) {
         return null;
     ```

The reason this issue appears **specifically on `/create` in Issuance LC** (and not on other pages or the list table) comes down to three architectural differences:

---

### 1. Form Page (`/create`) Has No Automatic Background Polling / Window Refetch
* **On table/list pages (like `/v2/import-lc/issuance-lc`):**
  Table views use data-fetching hooks (e.g. TanStack React Query) with `refetchOnWindowFocus: true`. When you switch back to Tab 2, a network request is immediately dispatched. Because `access-token` was deleted by Tab 1, that request fails with a `401 Unauthorized`, which dispatches the `showDialog` event.
  [`HostAuthGate.tsx`](file:///C:/Work/qcash-ui/components/providers/HostAuthGate.tsx#L286-L288) intercepts `showDialog`:
  ```tsx
  if (sessionDialogPending) {
    return <>{children}</>; // Keeps the UI mounted!
  }
  ```
  This keeps the layout alive and opens the **Session Expired Modal** instead of blanking out.
* **On `/create`:**
  The form is an in-memory multi-step wizard (`Page1` through `Page5`). Once system parameters load on initial mount, **there are no background polling requests or window-focus fetches**. 
  When Tab 1 deletes `access-token`, `showDialog` is **never dispatched**, so `sessionDialogPending` remains `false`. `HostAuthGate` drops straight into:
  ```tsx
  if (!token || !isHostValidated || !briAuth.isAuthoritiesReady || !hasMountedRef.current) {
    return null; // Tears down the entire page -> Blank White Screen
  }
  ```

---

### 2. Centralized Auth Migration (`HostAuthGate`) vs Legacy Pages
* The URL `http://internal-service.example.com` hosts two applications:
  1. **Legacy modules** (running on `addons-web-client` without `/v2/` prefix, such as standard fund transfer or old account statement).
  2. **Migrated modules** (running on `qcash-ui` under `/v2/`, including `issuance-lc`).
* Legacy pages **do not have [`HostAuthGate`](file:///C:/Work/qcash-ui/components/providers/HostAuthGate.tsx)**. They rely on per-page `guard()` calls that redirect directly via:
  ```ts

   if (!token || !isHostValidated || !briAuth.isAuthoritiesReady || !hasMountedRef.current) {
   ```
