When creating a transaction in the Fund Transfer module (EFT: **BI-FAST**, **Kliring**, and **RTGS**), the beneficiary account information provides an inline edit button for the **Beneficiary Account Name**.

Below is the detailed trace of the rendering logic and click interactions across the codebase.

---

### 1. Where the Edit Button Exists

The inline edit icon button for beneficiary information is implemented in the following transaction creation forms:
- **BI-FAST**: [`components/form/bifast/index.tsx:L1065-L1135`](file:///D:/work/qcash-ui-fund-transfer/components/form/bifast/index.tsx#L1065-L1135)
- **Kliring**: [`components/form/kliring/index.tsx:L964-L1056`](file:///D:/work/qcash-ui-fund-transfer/components/form/kliring/index.tsx#L964-L1056)
- **RTGS**: [`components/form/rtgs/index.tsx:L1089-L1180`](file:///D:/work/qcash-ui-fund-transfer/components/form/rtgs/index.tsx#L1089-L1180)

*(Note: In **IFT**, **Online Transfer**, and **SWIFT**, beneficiary details are presented in a read-only alert card or direct select input without an inline edit toggle).*

---

### 2. Logic for Rendering the Edit Button

#### A. Section Display Conditions
The Beneficiary Account Name input and its Edit button container are rendered when **all** of the following conditions are met:
```tsx
watch("receiver.receiverAccountBalance") !== "" &&
!watch("receiver.isManualInput") &&
!watch("receiver.isBeneficiaryFav")
```
- **`receiverAccountBalance !== ""`**: An account inquiry/validation has been successfully executed and returned valid account info.
- **`!receiver.isManualInput`**: The user is using inquiry-based account lookup rather than manual input mode.
- **`!receiver.isBeneficiaryFav`**: The account was **not** selected from Beneficiary Favorites (saved favorites lock the name from inline editing).

#### B. Button State Logic (`editBeneficiary`)
Each form tracks a local state: `const [editBeneficiary, setEditBeneficiary] = useState<boolean>(false);`

| State | UI Rendered | Input Disabled State |
|---|---|---|
| **`!editBeneficiary` (Default)** | Edit button (`RiEdit2Fill` icon) with `variant="ghost-info"`, `id="reditBenef"` | `<Input id="receiverAccountName" disabled={!editBeneficiary ...} />` (**Disabled**) |
| **`editBeneficiary === true` (Editing)** | Replaced by **Save** (`RiCheckFill`) and **Cancel** (`RiCloseFill`) buttons | `<Input id="receiverAccountName" disabled={false} />` (**Enabled**) |

---

### 3. What Happens When You Click It

#### Step 1: Clicking the Edit Button (`#reditBenef`)
```tsx
onClick={() => setEditBeneficiary((prev) => !prev)}
```
1. **Unlocks the Input Field**: `editBeneficiary` is set to `true`, removing the `disabled` state from `receiverAccountName`.
2. **Allows Custom Name Editing**: The user can modify the beneficiary account name (with regex sanitization allowing valid alphanumeric and punctuation characters, max length 150).
3. **Displays Confirmation Buttons**: The edit icon transforms into two action buttons:
   - **Save button (`#saveBenef`)**: Icon `RiCheckFill`, `variant="ghost-success"`. Disabled if the name is empty.
   - **Cancel button (`#cancelBenef`)**: Icon `RiCloseFill`, `variant="ghost-danger"`.
4. **Locks Transaction Submission**: The main form submit button (`#add`) is automatically disabled while editing (`disabled={... || editBeneficiary || ...}`).

---

#### Step 2: Clicking the Save or Cancel Button

- **Save Button Clicked (`#saveBenef`)**:
  ```tsx
  onClick={() => setEditBeneficiary((prev) => !prev)}
  ```
  - Toggles `editBeneficiary` back to `false`.
  - The newly entered beneficiary name is retained in the form state (`receiver.receiverAccountName`).
  - The input field is disabled again, and the form submit button is re-enabled.

- **Cancel Button Clicked (`#cancelBenef`)**:
  ```tsx
  onClick={() => {
    // Reverts or keeps previous value
    setEditBeneficiary((prev) => !prev);
  }}
  ```
  - Toggles `editBeneficiary` back to `false`.
  - Exits edit mode and locks the field.
