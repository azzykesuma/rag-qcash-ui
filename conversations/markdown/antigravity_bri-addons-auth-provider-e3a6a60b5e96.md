### 2. Lokasi Kode `.split()` pada `@bri/addons-auth-provider`

Pada repository `@bri/addons-auth-provider`, pemanggilan `.split` ada di beberapa titik kritis yang tidak memiliki *null/undefined-safety guard*:

#### A. Route Change Listener (`src/auth.tsx` / `dist/src/auth.js:1018-1019`)
```typescript
const handleRouteChangeStart = (url: any) => {
  const newPath = url.split("?")[0];
  const currentPath = prevPathnameRef.current.split("?")[0];
  if (newPath !== currentPath) {
    prevPathnameRef.current = url;
  }
};
router.events.on("routeChangeStart", handleRouteChangeStart);
```
* **Penyebab**: Jika Next.js router memicu event `routeChangeStart` dengan `url` bernilai `undefined`, atau jika `prevPathnameRef.current` belum terinisialisasi (`undefined`), pemanggilan `.split("?")[0]` langsung melempar:
  `TypeError: Cannot read properties of undefined (reading 'split')`.

#### B. Mapping Hak Akses / Authorities (`dist/src/auth.js:434` & `dist/utils/auth.js:80`)
```typescript
productRole = productRole.map((e) => e.split(":")[0]);

// dan di checkAuthority:
mappingStep(
  ((_a = authorities.get(module)) ?? [`${module}:guest`])
    .map((a) => a.split(":")[1])
    .filter((a) => a !== "-")[0]
) === step;
```
* **Penyebab**: Jika backend atau token session mengembalikan data otoritas yang berisi elemen `null`/`undefined` di dalam array (misal `[undefined]` atau slot kosong), iterasi `.map` akan mengeksekusi `undefined.split(":")`.

#### C. User Service Activity Logs (`dist/services/user.js:332`)
```typescript
const getActivityLogs = async (params) => {
  const { page, limit, search, filter } = params;
  const split = filter.split(","); // <-- crash jika filter tidak dikirim
  ...
};
```
* **Penyebab**: Parameter `filter` tidak memiliki *default value* atau *optional chaining*. Jika fungsi ini dipanggil tanpa `filter`, akan langsung crash saat membaca `filter.split(",")`.

### 3. Mengapa Terpicu Saat Memuat Template?

Ada 3 skenario utama yang dapat memicu crash ini saat klik **"Use Template"**:

1. **Efek Samping Route / Navigation Listener di Host MFE**  
   Saat modal template ditutup (`hideTemplateModal()`) atau terjadi perubahan step/URL di host container (`internal-service.example.com`), event `routeChangeStart` tertrigger dengan `url` bernilai `undefined`, sehingga fungsi `handleRouteChangeStart` di provider melempar error.
2. **Payload Template ID 6 Memiliki Properti yang `undefined`**  
   Di network tab terlihat request `GET /bg/v2/issuing/template/6` menghasilkan status **200 OK**. Namun, jika di dalam [`transformBgIssuingDetailToFormValues`](file:///C:/Work/qcash-ui-digi-guarantee/features/bg-issuing/utils/transform-detail-to-form.ts#L36) atau fungsi pendukungnya ada manipulasi string data template menggunakan `.split()` (seperti parsing alamat, parsing format file/dokumen, atau parsing nomor rekening) pada field yang nilainya `undefined` dari backend template, eksekusi akan *throw* sebelum state tersimpan.
3. **Intersepsi Request / Refresh Session oleh Axios Interceptor**  
   Jika pemanggilan template memicu evaluasi ulang auth interceptor di `@bri/addons-auth-provider`, dan data user/roles di session storage tidak lengkap, fungsi mapping `productRole.map((e) => e.split(":"))` akan gagal.

---

### 4. Rekomendasi Solusi

1. **Pada `@bri/addons-auth-provider`**:
   Tambahkan fallback / optional chaining untuk semua operasi split:
   ```typescript
   // Pada handleRouteChangeStart:
   const newPath = (url ?? "").split("?")[0];
   const currentPath = (prevPathnameRef.current ?? "").split("?")[0];

   // Pada authorities mapping:
   productRole = (productRole || []).filter(Boolean).map((e) => e?.split(":")?.[0] ?? "");

   // Pada user service:
   const split = (filter || "").split(",");
   ```

2. **Pada [`features/bg-issuing/components/form/bg-issuing-form.tsx`](file:///C:/Work/qcash-ui-digi-guarantee/features/bg-issuing/components/form/bg-issuing-form.tsx)**:
   Tambahkan `console.error(error)` di dalam blok `catch` pada `handleUseTemplate` agar stack trace lengkap (nama file dan baris penyebab asli) dapat langsung diperiksa di Console DevTools.

   - **TETAPI**, jika untuk suatu produk tertentu backend mengirimkan array yang memiliki elemen kosong/rusak, misalnya:
     - `authorities: [undefined]` atau `authorities: [null]`
     - `authorities: ["maker:create", undefined]`
     - Sparse array dari hasil serialisasi JSON/Redis
   - Maka `productRole` adalah array yang berisi elemen `undefined`.
4. Ketika dijalankan `.map((e) => e.split(":")[0])`:
   - `e` bernilai `undefined`.
   - Eksekusi `undefined.split(":")` **langsung melempar runtime error:**
     > `TypeError: Cannot read properties of undefined (reading 'split')`

### 3. Rekomendasi Solusi / Fix pada `@bri/addons-auth-provider`

Agar kode kebal terhadap data `authorities` yang tidak lengkap atau mengandung nilai `null`/`undefined`, baris 486–488 di `src/auth.tsx` perlu ditambahkan filter dan optional chaining:

```typescript
// SEBELUM:
let productRole = a.get(productValue) || [];
productRole = productRole.map((e) => e.split(":")[0]);

// SESUDAH (Defensive & Aman):
let productRole = a.get(productValue) || [];
productRole = (Array.isArray(productRole) ? productRole : [])
  .filter((e): e is string => typeof e === "string" && Boolean(e.trim()))
  .map((e) => e.split(":")[0]);
```

> [!TIP]
> Dengan memfilter `typeof e === "string"` sebelum `.split(":")`, provider tidak akan pernah mengalami crash meskipun backend mengirimkan array kosong, elemen `null`, ataupun format yang belum terdefinisi pada user role tersebut.
