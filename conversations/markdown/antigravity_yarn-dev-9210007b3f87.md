## Turn 133: Assistant

### Cause of the Error
The error occurred because of nested unescaped double quotes in:
```typescript
label: "t("form.activityFilter.all")",
```
1. In TypeScript/JavaScript, the inner quotes prematurely close the string at `"t("`, causing TypeScript to parse `form` as an identifier/shorthand property in the object.
2. In addition, [`constants/common.ts`](file:///C:/Work/qcash-ui-account-receivable/constants/common.ts) is a static constants file outside React components/hooks, so `t(...)` is not available in module scope.

---

### Solution
Use the translation key string directly: `"form.activityFilter.all"`. The UI layer (`FilterItems`, `Select`, `translateOptions`) runs `t(option.label)` on render, which translates this key into `"All"` (EN), `"Semua"` (ID), or `"全部"` (ZH).

In [`constants/common.ts`](file:///C:/Work/qcash-ui-account-receivable/constants/common.ts#L54-L74):

```typescript
export const defaultSelectValue: any = Object.assign(
  (t?: (key: string) => string) => ({
    label: t ? t("form.activityFilter.all") : "All",
    value: "0",
  }),
  {
    label: "form.activityFilter.all",
    value: "0",
  },
);

export const defaultSelectValue2: any = Object.assign(
  (t?: (key: string) => string) => ({
    label: t ? t("form.activityFilter.all") : "All",
    value: "",
  }),
  {
    label: "form.activityFilter.all",
    value: "",
  },
);
```

### Is there any configuration missing in `qcash-ui`?

**No configuration is missing in `qcash-ui`.**

In the QLola Micro-Frontend (MFE) architecture:
1. **`qcash-ui`** is only the host container/shell — it only maintains global/shared translations (e.g. `common.json`).
2. Domain-specific keys belong to **`qcash-ui-account-receivable`** inside its own translation bundle:
   - [`public/locales/en/account-receivable.json`](file:///C:/Work/qcash-ui-account-receivable/public/locales/en/account-receivable.json#L35)
   - [`public/locales/id/account-receivable.json`](file:///C:/Work/qcash-ui-account-receivable/public/locales/id/account-receivable.json#L35)
   - [`public/locales/zh/account-receivable.json`](file:///C:/Work/qcash-ui-account-receivable/public/locales/zh/account-receivable.json#L35)
   Both keys are already properly defined there:
   - `data.creditAccountNumber`: `"Credit Account Number"` / `"Nomor Rekening Kredit"` / `"信用帐号"`
   - `data.transaction.status`: `"Transaction Status"` / `"Status Transaksi"` / `"交易状态"`

### What was actually missing here in `qcash-ui-account-receivable`

The issue was in **[`hooks/use-table-columns.ts`](file:///C:/Work/qcash-ui-account-receivable/hooks/use-table-columns.ts)**:

1. **`t` was not passed to `getLastColumns`**:
   In [`hooks/use-table-columns.ts`](file:///C:/Work/qcash-ui-account-receivable/hooks/use-table-columns.ts#L41-L50), `getLastColumns` builds the trailing table columns (`credit_account_number`, `status`, `actions`). Because `t` was omitted, [`getLastColumns`](file:///C:/Work/qcash-ui-account-receivable/components/local/table/table-columns/index.tsx#L37) fell back to its default identity function:
   ```typescript
   t = (k: string) => k
   ```
   This caused `t("data.creditAccountNumber")` and `t("data.transaction.status")` to return the raw keys as strings.
2. **Missing dependency on language changes**:
   `useTableColumns` memoized `columns` solely on `[payload]`, preventing columns from re-rendering when the active language changed.

---

### Fix Applied

1. **[`hooks/use-table-columns.ts`](file:///C:/Work/qcash-ui-account-receivable/hooks/use-table-columns.ts)**:
   - Added `const { t, language } = useTranslate()` and forwarded `t` to `getLastColumns({ ..., t })`.
   - Added `t`, `language`, and the column slices to the `useMemo` dependencies so the headers re-render immediately upon language switch.
2. **[`containers/receivable-action/search-batch/view/table.tsx`](file:///C:/Work/qcash-ui-account-receivable/containers/receivable-action/search-batch/view/table.tsx#L330-L340)**:

### Cause of the Issue

1. **Why it was displaying weirdly:**
   - Filter mapping states across containers (e.g., `mandateType`, `product`, `mandateCategory`) initialize with placeholder dummy objects such as `[{ value: "", label: "" }]`.
   - When the dropdown popover opened, `<Select menuIsOpen ... />` forced the dropdown menu open. Because `options` contained an item with an empty label (`""`), `react-select` rendered a blank option item with default hover/selected blue background—appearing as an empty, awkward light-blue box.

---

### Solution Implemented

1. **Disable Filter Input When No Data Is Present**:
   - Added a `hasFilterData` helper in [`components/local/filter-items/index.tsx`](file:///C:/Work/qcash-ui-account-receivable/components/local/filter-items/index.tsx):
     - Returns `false` when `options` is empty, undefined, contains only empty placeholders (`{ label: "", value: "" }`), or contains only the fallback "All" option without any real selectable data.
     - When `hasFilterData` is `false`, the filter item sets `disabled: true`.
2. **Badge & Popover Disabling in [`new-filter-input/index.tsx`](file:///C:/Work/qcash-ui-account-receivable/components/local/table/new-filter/new-filter-input/index.tsx)**:
   - When `disabled` is true, [`PopoverMenu`](file:///C:/Work/qcash-ui-account-receivable/components/globals/index.tsx#L151) receives `disabled={true}`, preventing the popover from opening on click.
   - The filter pill receives `rcv-cursor-not-allowed rcv-opacity-50`.
   - The clear ('X') icon is rendered gray and made non-interactive (`disabled ? "rcv-pointer-events-none" : "pointer-events-auto"`).
3. **Select State & Option Sanitization**:
   - Passed `menuIsOpen={hasData}`, `disabled={!hasData}`, and `isDisabled={!hasData}` to `<Select>`.
   - Stripped dummy empty placeholder items (`cleanAndTranslateOptions`) so blank option rows are never passed to `<Select>`.

Alasannya dan cara kerjanya adalah sebagai berikut:

---

### 1. Bagaimana i18next Membacanya
Di `i18next`, pemisah hierarki (nesting) secara *default* hanyalah tanda titik `.` (`keySeparator: "."`). 
Karakter spasi maupun simbol seperti `&` adalah karakter string yang valid untuk sebuah *property key* di JSON/JavaScript:

```json
{
  "navigation": {
    "menu": {
      "Collections Inquiry & Reports": "收款查询与报告",
      "Account Collection Dashboard": "账户收款仪表板"
    }
  }
}
```

Buktinya, pada screenshot yang Anda kirimkan, **semua menu lain yang memiliki spasi juga berhasil diterjemahkan** menggunakan pola yang sama persis:
- `"Single Collection"` &rarr; `navigation.menu.Single Collection` &rarr; **`单笔收款`**
- `"Direct Debit"` &rarr; `navigation.menu.Direct Debit` &rarr; **`直接借记`**
- `"Bulk Collection"` &rarr; `navigation.menu.Bulk Collection` &rarr; **`批量收款`**
- `"Maker Confirmation"` &rarr; `navigation.menu.Maker Confirmation` &rarr; **`厂商确认`**

---

### 2. Kenapa Format Kodenya Seperti Itu?
Di [`MenuMapper.tsx`](file:///C:/Work/qcash-ui-header-footer/layouts/default/container/menu/components/MenuMapper.tsx#L68):
```typescript
{t(`navigation.menu.${item.label}`, item.label)}
```
String `item.label` **bukan dibuat secara manual (bukan camelCase)** oleh frontend developer, melainkan diambil langsung dari data menu yang dikembalikan oleh API Auth backend. Developer hanya menambahkan prefix template string ``navigation.menu.${item.label}``.

---

### 3. Kenapa `"Collections Inquiry & Reports"` Masih Bahasa Inggris?
Ada beberapa kemungkinan umum yang sering terjadi di database translasi:

1. **Perbedaan Penulisan `&` vs `and`**:
   Saat data di-insert ke database translasi backend, mungkin ditulis menggunakan kata **`and`** alih-alih simbol **`&`**:
   `navigation.menu.Collections Inquiry and Reports`
2. **HTML Entity Encoding**:
   Terkadang karakter `&` di-encode oleh sistem backend/database menjadi `&amp;` (`Collections Inquiry &amp; Reports` &harr; `Collections Inquiry &amp; Reports`), sehingga key-nya tidak cocok (*miss*).
3. **Trailing Space**:
   Ada spasi berlebih di database (misal `"Collections Inquiry & Reports "` atau `" Collections Inquiry & Reports"`).
4. **Key Belum Terdaftar**:
   Key tersebut belum pernah di-insert ke database tabel translasi untuk module `header-footer`.

Ketika key tidak cocok persis 100%, `i18next` akan mengembalikan parameter kedua (fallback-nya), yaitu string label aslinya: `"Collections Inquiry & Reports"`.

## Turn 1220: Assistant

Berdasarkan investigasi menyeluruh pada alur *translation* dan *network requests* (dari shell `qcash-ui`, remote MFE `qcash-ui-account-receivable`, hingga API backend), berikut adalah **analisis komprehensif seluruh issue performa translasi & duplikasi request**:

---

### 1. Mengapa Translation API Di-fetch Berulang Kali? (*The Cascading Waterfall*)

Dalam Network Tab terlihat belasan request translasi (`translations?lang=...`). Hal ini disebabkan oleh **4 faktor yang saling bertumpuk**:

```
[Page Load]
    │
    ├── 1. Shell (ni18n.config.ts)
    │      ├── Fetch Active Lang:  [translation.json, header-footer, common] (3 request)
    │      └── Fetch Fallback(en): [translation.json, header-footer, common] (3 request)
    │
    ├── 2. Module Federation Loader (dynamicLoadLocales in qcash-ui)
    │      └── Re-fetch "common" & "header-footer" untuk remote module (2 request)
    │
    ├── 3. Remote MFE Hook (useTranslate in account-receivable)
    │      ├── Fetch account-receivable (Active Lang)
    │      └── Fetch account-receivable (en Fallback)
    │
    └── 4. HTTP Headers Backend
           └── Cache-Control: no-store, no-cache, max-age=0 (Browser dilarang me-cache)
```

#### A. Konfigurasi `fallbackLng: "en"` di Shell Container
Di `qcash-ui/ni18n.config.ts`, terdapat konfigurasi:
```typescript
fallbackNS: ["common", "header-footer", "translation"],
fallbackLng: "en",
```
Setiap kali halaman dibuka dalam bahasa `ID` atau `ZH`, library `i18next` secara otomatis **mem-fetch dua kali**:
1. Bundle untuk bahasa aktif (`lang=zh` atau `lang=id`).
2. Bundle untuk bahasa *fallback* (`lang=en`).

#### B. Redundansi pada `dynamicLoadLocales` (Shell Container)
Di `qcash-ui/services/federation/utils/i18n.ts` baris 164:
```typescript
const nss = Array.from(new Set([...requestedNs, "common", "header-footer"]));
```
Setiap kali suatu micro-frontend di-mount, fungsi ini secara *hardcoded* **mem-fetch ulang namespace `"common"` dan `"header-footer"`**, meskipun kedua namespace tersebut sudah di-load oleh shell pada inisialisasi awal.

#### C. Backend Melarang Browser Cache (`no-store`)
Hasil inspeksi langsung response headers dari endpoint `/api/language/v1/translations`:
```http
pragma: 'no-cache'
expires: off;
etag: off;
cache-control: 'no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0';
```
Backend secara eksplisit mengirimkan `no-store` dan menonaktifkan `ETag`. Akibatnya:
- Browser **dilarang menyimpan cache** di Memory Cache maupun Disk Cache.
- Tidak ada mekanisme `304 Not Modified`.
- Setiap navigasi atau remount akan selalu melakukan *full roundtrip* ke server.

---

### 2. Mengapa Mapping API (`mandate-category`, `batch-type`) Terpanggil Dua Kali?

Di Network tab pada screenshot sebelumnya, terlihat endpoint seperti `mandate-category` dan `batch-type` di-request 2x bersamaan saat halaman dibuka.

**Penyebabnya ada di [view.tsx](file:///C:/Work/qcash-ui-account-receivable/containers/maker-confirmation/search-batch/view/view.tsx#L218-L222):**

```typescript
// containers/maker-confirmation/search-batch/view/view.tsx
const { loadingMapping } = useSearchFormMappings({
  companyId,
  searchCriteria,
  formMappings,
  setFormMappings,
  requests: [
    getMandateTypeMappings(),      // <-- Dijalankan langsung saat render
    getMandateCategoryMappings(),  // <-- Dijalankan langsung saat render
    getBatchTypeMappings(),        // <-- Dijalankan langsung saat render
    ...
  ],
  ...
});
```

**Masalah Eksekusi:**
- Menuliskan `getMandateCategoryMappings()` langsung di dalam argumen hook membuat *Promise*-nya langsung di-trigger **setiap kali function component me-render**.
- Ketika komponen mengalami *re-render* di awal (misalnya saat `router.isReady`, `useAuth` ter-hydrate, atau state berubah), array tersebut dievaluasi ulang dan membuat koneksi HTTP baru sebelum `useEffect` sempat mendeteksi cache.

---

### 3. Masalah Bundle Size & Memory di Remote MFE

Di [hooks/use-translate.ts](file:///C:/Work/qcash-ui-account-receivable/hooks/use-translate.ts#L3-L8):
```typescript
import en from "@/public/locales/en/account-receivable.json";
import id from "@/public/locales/id/account-receivable.json";
import zh from "@/public/locales/zh/account-receivable.json";
import enCommon from "@/public/locales/en/common.json";
import idCommon from "@/public/locales/id/common.json";
import zhCommon from "@/public/locales/zh/common.json";
```
- **Bundle Bloat:** Seluruh file JSON translasi (~74 KB) di-import secara statis ke dalam bundle JavaScript utama. Padahal translasi sudah diambil secara dinamis dari API backend.
- **Multiple Event Listeners:** Setiap komponen yang memanggil `const { t } = useTranslate()` mendaftarkan event listener tersendiri ke `window.addEventListener("ADDONS_CHANGE_LANGUAGE")` dan `window.addEventListener("storage")`. Jika dalam satu halaman ada 30 komponen memanggil `useTranslate`, terdapat 60 event listener yang aktif bersamaan.

---

### 4. Inkonsistensi Data di Database Central (`qcash_language`)

Sesuai screenshot query database yang Anda tampilkan:
- Pada `module = common`, key `module.mandateManagement` untuk `language_code = id` masih tersimpan nilai bahasa Inggris: **`"Mandate Management"`**.
- Di `module = header-footer`, menu `navigation.menu.Mandate Management` juga tersimpan teks bahasa Inggris untuk `id`.

Hal ini menyebabkan frontend terpaksa membuat *layer patching* (`mapTranslate`) di sisi client untuk menambal teks yang belum diterjemahkan di level backend.

---

### Rekomendasi Solusi & Optimasi

| Area | Tindakan Rekomendasi | Estimasi Dampak |
| :--- | :--- | :--- |
| **Mapping API (Local MFE)** | Ubah `requests` di `useSearchFormMappings` agar berbentuk fungsi lazily-called `() => getMandateCategoryMappings()` atau dibungkus `useMemo` agar tidak langsung trigger request saat re-render. | Mengeliminasi **50% duplikasi request mapping** saat page mount. |
| **Translation Fetch (Shell)** | Di `dynamicLoadLocales` (`qcash-ui`), tambahkan pengecekan `i18n.hasResourceBundle(lng, ns)`. Jika `common` dan `header-footer` sudah ada di memori, jangan di-fetch ulang. | Mengurangi **4–6 request translasi** per pergantian modul. |
| **HTTP Caching (Backend)** | Tambahkan header cache pada `/api/language/v1/translations`, misalnya `Cache-Control: public, max-age=300, stale-while-revalidate=3600` dan dukung `ETag`. | Mengeliminasi roundtrip jaringan untuk translasi yang tidak berubah (**instant load 304/Disk Cache**). |
| **Listener Cleanup (Local MFE)** | Buat store / context tunggal untuk sinkronisasi bahasa (Singleton listener), sehingga `useTranslate` hanya mengonsumsi state tanpa harus mendaftarkan listener `window` di setiap komponen. | Mengurangi overhead memori & re-render cascade saat ganti bahasa. |

### 2. Singleton Event Listener untuk Sinkronisasi Bahasa (`useTranslate`)

* **Problem sebelumnya**: Setiap komponen yang memanggil `const { t } = useTranslate()` menambahkan listener tersendiri ke `window.addEventListener("ADDONS_CHANGE_LANGUAGE")` dan `window.addEventListener("storage")`. Pada halaman kompleks dengan puluhan sub-komponen, terdapat puluhan listener identik di window yang memicu multiple re-render cascade saat bahasa berganti.
* **Solusi**:
  Di [hooks/use-translate.ts](file:///C:/Work/qcash-ui-account-receivable/hooks/use-translate.ts#L52-L115), implementasi diubah menjadi **Module-Level Singleton Store**:
  - Hanya ada **1 listener global** di level `window` untuk seluruh lifecycle MFE.
  - Setiap instance `useTranslate` mendaftar ke internal subscriber `Set` tanpa membuat listener DOM baru.
  - Saat ada pergantian bahasa, handler tunggal mengecek perubahan, memanggil `i18n.changeLanguage()`, dan menotifikasi komponen secara terkoordinasi.
