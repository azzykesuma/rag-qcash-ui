### 2. Dari Mana Asal Error Tersebut?

Di [`next.config.ts`](file:///D:/work/qcash-ui-dashboard-dhe/next.config.ts), proyek menggunakan:
- `next-rspack`
- `ModuleFederationPlugin` dari `@module-federation/enhanced/rspack`

Saat melakukan bundling container remote / shared dependency, plugin Module Federation Rspack (`@rspack/core`) membuat virtual entrypoint runtime menggunakan sintaks inline *matchResource*:
```javascript
@module-federation/runtime/rspack.js!=!data:text/javascript,${content}
```
Bagian resource-nya adalah sebuah URI `data:text/javascript,...`.

---

### 3. Mengapa Error Ini Bisa Terjadi? (Root Cause Timeline)

Penyebab utamanya adalah **perubahan Docker base image** antara branch `dev` dan `prerelease`.

#### Perbandingan dengan Branch `dev` (Build #199 Sukses):
Di branch `dev`, build Bamboo terbaru (**Build #199**) berhasil dengan log:
```text
✓ Creating an optimized production build ...
✓ Compiled successfully in 16.6s
```
Karena di `dev`, base image [Dockerfile](file:///D:/work/qcash-ui-dashboard-dhe/Dockerfile#L1) menggunakan:
```dockerfile
FROM internal-service.example.com/cmp/base-image/imbios/bun-node:1.3.8-24.13.0-slim AS base
```
Image ini berisi **Bun 1.3.8 + Node.js 24**. Ketika `bun run next build` dijalankan, Bun menyerahkan eksekusi Next.js ke binary `node` (Node.js runtime V8). Di bawah runtime Node.js, binding native `@rspack/core` berjalan normal dan dapat meng-handle virtual `data:` URI Module Federation.

#### Apa yang Terjadi di `prerelease` (Build #43 s/d #50):
1. **Build #43 – #47**: Build sebelumnya gagal di stage `deps` (`bun install`) karena HTTP 401 Unauthorized saat mengambil package internal `@bri/addons-auth-provider` dari Nexus.
2. **Commit `e9c4beb` & `0ce4e82`**: Saat mencoba memperbaiki otentikasi Nexus/Bitbucket, base image di [Dockerfile](file:///D:/work/qcash-ui-dashboard-dhe/Dockerfile#L1) diubah menjadi:
   ```dockerfile
   FROM internal-service.example.com/cmp/base-image/oven/bun:1.3.8-debian AS base
   ```
3. **Dampaknya**:
   - Image `oven/bun:1.3.8-debian` **hanya berisi runtime Bun** (tidak ada Node.js).
   - `bun install` berhasil melewati stage `deps`.
   - Namun begitu masuk ke stage `builder`, perintah `bun run next build` terpaksa dieksekusi langsung oleh engine JavaScript runtime **Bun** (bukan Node.js).
   - Di dalam environment runtime Bun murni, binding native Rust Rspack (`@rspack/core`) mengalami inkompatibilitas dalam me-resolve inline matchResource scheme `data:text/javascript,...`, sehingga Rspack melempar error:
     `"is not handled by plugins (Unhandled scheme)"`.

---

### 4. Solusi / Next Action

Kembalikan base image di [Dockerfile](file:///D:/work/qcash-ui-dashboard-dhe/Dockerfile#L1) pada branch `prerelease` menggunakan image yang memiliki Node.js runtime:

```dockerfile
FROM internal-service.example.com/cmp/base-image/imbios/bun-node:1.3.8-24.13.0-slim AS base
```

Tetap pertahankan penanganan kredensial Nexus (`NEXUS_USERNAME`, `NEXUS_PASSWORD`) dan Bitbucket token di stage `deps` yang sudah berhasil. Dengan base image `imbios/bun-node`, `next build` akan kembali dieksekusi di Node.js dan build Rspack akan sukses seperti di branch `dev`.

   ```json
   "addons-dhe-contracts": "git+https://internal-service.example.com/scm/addons/addons-dhe-contracts.git#55953b61dae"
   ```
   Karena `GIT_CONFIG_COUNT` tidak dikenali oleh Git 2.30.2, request `git clone` dikirim tanpa header `Authorization: Bearer ...`, sehingga Bitbucket menolak clone dengan HTTP 401 dan instalasi dependensi gagal.

---

### 3. Solusi

Gunakan perintah standar `git config --global` yang kompatibel dengan semua versi Git (seperti yang digunakan pada branch `dev`), lalu hapus/unset setelah `bun install` selesai:

```dockerfile
ARG bitbucketForexToken
ARG bitbucketToken
ARG BITBUCKET_TOKEN

...

RUN token="${bitbucketForexToken:-${bitbucketToken:-$BITBUCKET_TOKEN}}" && \
    if [ -n "$token" ]; then \
        git config --global http.https://internal-service.example.com/.extraHeader "Authorization: Bearer ${token}"; \
    fi && \
    bun install --frozen-lockfile; \
    install_status=$?; \
    git config --global --unset-all http.https://internal-service.example.com/.extraHeader || true; \
    rm -f ~/.npmrc /tmp/pass ~/.gitconfig; \
    exit "${install_status}"
```

Keunggulan:
- Kompatibel penuh dengan Git 2.30.2 di `imbios/bun-node`.
- Mendukung fallback token (`bitbucketForexToken`, `bitbucketToken`, maupun `BITBUCKET_TOKEN`).
- Membersihkan kredensial (`~/.npmrc`, `/tmp/pass`, `~/.gitconfig`) sehingga tidak tertinggal di layer image.
