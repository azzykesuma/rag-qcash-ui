## Turn 151: Assistant

### Root Cause

The `yarn build` failure was caused by two interrelated Webpack bundling issues during Next.js static page prerendering:

1. **Unconditional `config.target = "web"` and CSS loader rules**:
   In [next.config.js](file:///D:/work/qcash-ui-dashboard-merchant/next.config.js), `config.target = "web"` and the `style-loader` rules were applied to both server and client Webpack compilations. This disrupted Node.js module resolution during SSR and prerendering.
2. **`i18next-fs-backend` and `i18next-http-backend` ESM / Top-Level Await Conflict**:
   The ESM distributions of `i18next-fs-backend` and `i18next-http-backend` contain top-level `await` (`await import('node:fs')`), causing Webpack to classify them as asynchronous modules. When CommonJS packages (such as `ni18n`) required them synchronously, the required module returned `undefined`, triggering:
   ```
   Error: You are passing a wrong module! Please check the object you are passing to i18next.use()
   ```

---

### Solution

In [next.config.js](file:///D:/work/qcash-ui-dashboard-merchant/next.config.js):

1. Scoped `style-loader` and `config.target = "web"` strictly to client builds (`!isServer`).
2. Added Webpack aliases to resolve `i18next-fs-backend` and `i18next-http-backend` to their synchronous CommonJS distributions (`/cjs`):

```javascript
  webpack: (config, options) => {
    const { isServer } = options;
    if (!isServer) {
      config.module.rules.push({
        test: /\.(css|s[ac]ss)$/i,
        use: ["style-loader", "css-loader", "postcss-loader"],
      });
      config.target = "web";
    }

    config.resolve = config.resolve || {};
    config.resolve.alias = {
      ...config.resolve.alias,
      "i18next-fs-backend": require.resolve("i18next-fs-backend/cjs"),
      "i18next-http-backend": require.resolve("i18next-http-backend/cjs"),
    };

    config.plugins.push(new NextFederationPlugin(federationConfig));
    return config;
  },
```
