## Turn 112: Assistant

**No**, this modal is **not** supposed to pop up automatically when visiting `/span/history?tab=void`. 

Here is how it is designed to work:

### 1. What the URL is supposed to show: The Void Table
Visiting `/span/history?tab=span-void` is meant to switch to the **"Void Transaction"** tab and render the **table/list** of transactions eligible for voiding.

### 2. When this modal is supposed to appear: Clicking the "Void" row action
Inside that table, each row has an **Action** column with a **"Void"** button ([containers/history.tsx#L490-L499](file:///C:/Work/qcash-ui-span/containers/history.tsx#L490-L499)):
* When a user clicks that **"Void"** button for a specific row, [`handleTask`](file:///C:/Work/qcash-ui-span/containers/history.tsx#L323-L345) triggers this modal ([`VoidActionModal`](file:///C:/Work/qcash-ui-span/components/modals.tsx#L113-L198)).
* The modal prompts for **Reason** and **OTP** to submit the void request to `/span/void/outbound/action`.

---

### Why nothing happened when visiting `?tab=void`
1. **Key Mismatch**: The tab key defined in [const/history.ts](file:///C:/Work/qcash-ui-span/const/history.ts#L24) is `span-void`, **not** `void`.
   * When [`initActiveTab`](file:///C:/Work/qcash-ui-span/containers/history.tsx#L871-L886) reads `query["tab"] === "void"`, `ItemTabHeader.find(...)` returns `undefined` and silently falls back to `span-upload`.
   * The correct URL param is:
     ```
     /span/history?tab=span-void
     ```
2. **Signer Authority Guard**: The tab is conditionally hidden if the user does not have `authority.approve` ([containers/history.tsx#L892-L897](file:///C:/Work/qcash-ui-span/containers/history.tsx#L892-L897)).

---
