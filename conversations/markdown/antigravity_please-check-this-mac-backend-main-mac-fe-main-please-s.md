## Turn 57: Assistant

If you want to run the migrations and seeders **inside the Docker container** rather than on your host machine, you can definitely do that! 

Running it inside the Docker container is often cleaner because it uses the container's environment and dependencies directly, and connects to the database via the internal Docker network.

Once you start the containers with `docker compose up -d`, you can run the migrations and seeds inside the `app` container by using `docker compose exec`:

#### 1. Run Migrations & Root Seed inside the container
```bash
docker compose exec app npx prisma migrate dev
```
*(This will generate the prisma client, apply migrations, and run `prisma/seed.ts` to create the root admin account).*

#### 2. Run the Dummy Seeder inside the container
```bash
docker compose exec app npx tsx prisma/seed-dummy.ts
```

### Why is there a difference?
* **Host Machine (Local)**: The `.env` database URL uses `localhost:5432` because your host machine connects to the mapped port on `localhost`.
* **Inside Docker**: The `app` container uses `db:5432` (overridden in `docker-compose.yml`) because containers on the same Docker network resolve the database container by its service name `db`. Running the command via `docker compose exec` runs it inside the `app` container using the container's network context.
