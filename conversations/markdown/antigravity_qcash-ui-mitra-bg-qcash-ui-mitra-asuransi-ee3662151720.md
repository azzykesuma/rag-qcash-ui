## Turn 130: Assistant

### 1. What does `<Container variant="qcash">` mean?

In the Q-Cash design system (and `qcash-global-component`):
* The default `<Container>` renders standard card styling (`bg-white`, `p-8`, `rounded`, `drop-shadow-md`).
* When `variant="qcash"` is set, it applies the updated **Q-Cash 2.0 card styling** (`!rounded-lg`, `!filter-none`, custom border/background styling without the legacy drop-shadow filter).

---

### 2. Why does the TypeScript error happen?

Look at how `ContainerProps` is defined in `@mf-types/qcash-global-component/_types/components/container/container.d.ts`:

```typescript
import { type VariantProps } from "class-variance-authority";

declare const containerVariants: (props?: ({
    variant?: "default" | "qcash" | null | undefined;
} & import("class-variance-authority/types").ClassProp) | undefined) => string;

export interface ContainerProps 
  extends React.HTMLAttributes<HTMLDivElement>, 
          VariantProps<typeof containerVariants> {
    customClassName?: string;
}
```

* The `variant` property is injected into `ContainerProps` via `VariantProps<typeof containerVariants>`, which comes from the **`class-variance-authority` (`cva`)** library.
* When `class-variance-authority` is **not installed** locally in `node_modules` (missing from `package.json`), TypeScript fails to resolve the `VariantProps` import.
* When TypeScript cannot resolve `VariantProps`, it evaluates `VariantProps<...>` to `{}` (empty).
* Consequently, `ContainerProps` falls back to just standard `React.HTMLAttributes<HTMLDivElement>`, which **does not have a `variant` property**, causing:
  ```
  Type error: Property 'variant' does not exist on type 'IntrinsicAttributes & ContainerProps'.
  ```

---

### 3. Why does Gym (CI/CD / Gym server) build/clear without it?

1. **Monorepo / Hoisted Dependencies in Gym Containers:**
   * In the Gym build container/runner, packages or dependencies are often resolved from a shared workspace / parent node_modules / monorepo cache where `class-variance-authority` was already hoisted by another package (like `@bri/addons-auth-provider` or other core UI packages).
2. **Fresh Local Isolation:**
   * When building in your standalone local repo folder with a fresh `yarn install`, Yarn only installs packages explicitly listed in `package.json`. Since `class-variance-authority` was missing from `package.json`, it was not in your local `node_modules`.
3. **Module Federation Type Bundling:**
   * Remote types generated by Webpack Module Federation (`@mf-types`) produce `.d.ts` files that import from `class-variance-authority`, expecting consumers to have it available in their typing environment.

---

### Solution
Adding `class-variance-authority` to `devDependencies` in `package.json`:
```bash
yarn add -D class-variance-authority
```
allows TypeScript to properly resolve `VariantProps` so `variant="qcash"` (and `variant="default"`) is recognized as valid on `<Container>`.
