### Executive Summary

The intermittent issue where `access-token` in `localStorage` becomes `"[object Object]"` and prompts a repeated relogin stems from a **contract mismatch between `qcash-ui` and `@bri/addons-auth-provider`**:

1. **`@bri/addons-auth-provider` expects `resolve` to be passed the new token string**:
   When an API call receives a `401`, the provider dispatches the `showDialog` event with a `{ resolve }` callback. The provider chains `.then((token) => ...)` onto that promise, expecting `token` to be a JWT string, and executes:
   ```javascript
   localStorage.setItem("access-token", token);
   originalRequest.headers["Authorization"] = "Bearer " + token;
   return customAxios(originalRequest);
   ```
2. **[`retryExceptionV2`](file:///C:/Work/qcash-ui/services/custom-axios.ts#L193-L223) passes an Axios Response Object to `resolve` instead of the token string**:
   In [`services/custom-axios.ts`](file:///C:/Work/qcash-ui/services/custom-axios.ts#L221), `retryExceptionV2` executes:
   ```typescript
   return resolve(customAxios(originalRequest));
   ```
   Passing an Axios Promise to `resolve` resolves the outer promise with the **Axios response object** (`{ status: 200, data: ..., headers: ... }`).
3. **The provider coerces the object to string**:
   `localStorage.setItem("access-token", token)` converts the object to `"[object Object]"`. It then retries the request with `Authorization: Bearer [object Object]`, receiving an immediate `401 Unauthorized` and re-triggering the session expired modal.

---

### Key Investigation Findings

#### 1. Contract Mismatch in `retryExceptionV2`
In [`hooks/use-modal-session-expired.tsx`](file:///C:/Work/qcash-ui/hooks/use-modal-session-expired.tsx#L256-L268):
- `performLogin` successfully fetches the new token string `atkn` and stores it into `localStorage`:
  ```typescript
  localStorage.setItem("access-token", atkn); // Valid JWT string
  ```
- Then [`retryExceptionV2`](file:///C:/Work/qcash-ui/services/custom-axios.ts#L193-L223) is called with `resolve` and `response: { token: atkn, ... }`.
- In [`services/custom-axios.ts`](file:///C:/Work/qcash-ui/services/custom-axios.ts#L148-L156), queued concurrent requests are correctly resolved with the token string:
  ```typescript
  processQueue({ error: null, token, queue }); // Calls prom.resolve(token) with JWT string
  ```
- However, for the primary request, line 221 does:
  ```typescript
  return resolve(customAxios(originalRequest)); // Passes Promise<AxiosResponse> to resolve!
  ```
- When `customAxios(originalRequest)` fulfills, the callback in `@bri/addons-auth-provider` receives `token = { data: ..., status: 200, ... }`.
- It executes `localStorage.setItem("access-token", token)`, overwriting the valid JWT string with `"[object Object]"`, and fires a secondary retry with `Bearer [object Object]`.

---

#### 2. Why Deleting the `login` Key Triggers This Flow
In [`components/ui/SessionExpiredNewQlola.tsx`](file:///C:/Work/qcash-ui/components/ui/SessionExpiredNewQlola.tsx#L43-L56):
```typescript
const loginLocalStorage = localStorage.getItem("login");
if (!loginLocalStorage) {
  setShouldDisabled(false);
  return;
}
```
- Normally, `login` exists (`username-companyCode-userID-companyID`), locking the username and company code fields (`shouldDisabled = true`).
- Deleting `login` enables input fields, but has side effects:
  1. [`useModalSessionExpired`](file:///C:/Work/qcash-ui/hooks/use-modal-session-expired.tsx#L318-L341) cannot split the `login` key, leaving `payload.userID = ""` and `payload.companyID = ""`.
  2. In [`useModalSessionExpired`](file:///C:/Work/qcash-ui/hooks/use-modal-session-expired.tsx#L120-L130), `isUserChanged` checks:
     ```typescript
     const isUserChanged = username && username !== "Guest" && username.toLowerCase() !== _uname.toLowerCase();
     ```
     If the user deleted `login` to unlock fields but typed the same username (or if `username` from `useAuth()` was `"Guest"`), `isUserChanged` evaluates to `false`.

---

#### 3. Why the Issue is Intermittent

1. **Race condition with `location.reload()`**:
   - On `/v2` or `/v2/homepage` (or when `isUserChanged` is true), [`useModalSessionExpired`](file:///C:/Work/qcash-ui/hooks/use-modal-session-expired.tsx#L128) calls `window.location.reload()`.
   - `location.reload()` is asynchronous and does not immediately halt JavaScript execution.
   - **Fast page unload**: If the browser tears down the document before `customAxios(originalRequest)` finishes, the `.then` never runs; the reloaded page boots with the valid token.
   - **Fast API response**: If `customAxios(...)` completes before the page unloads, `.then` runs and writes `"[object Object]"` into `localStorage` right before the reload. The newly loaded page boots with `"[object Object]"` and fails.
2. **Route dependency**:
   - On inner routes (e.g., `/v2/transaction-history`, `/v2/transfer`), `location.reload()` is **not** called. The retry executes directly in-page, making the overwrite consistent on those routes.
3. **Endpoint differences (`menu/me` vs other URLs)**:
   - If the `401` was triggered by `menu/me`, line 257 skips retry:
     ```typescript
     if (!originalRequest?.url?.endsWith("menu/me") && resolve && reject)
     ```
     In this case, `resolve` is never called, and `access-token` is never corrupted.
4. **HMAC Signature failure with empty `userID`/`companyID`**:
   - Because `login` was deleted, `companyID` and `userID` are empty strings.
   - For POST/PUT requests, [`processJsonData`](file:///C:/Work/qcash-ui/services/custom-axios.ts#L280-L292) generates `Grpc-Metadata-Signature` with empty `&companyid:&userid:`. If the backend rejects the signature (400 Bad Request), `resolve` does not resolve with a `200` response object. GET requests bypass signature creation and fulfill `resolve`, triggering the overwrite.

---

### Recommended Solutions

1. **Resolve with the token string in [`services/custom-axios.ts`](file:///C:/Work/qcash-ui/services/custom-axios.ts#L214-L221)**:
   In `retryExceptionV2` (and `retryException`), fulfill `resolve` with `token` (the JWT string), matching `processQueue`:
   ```typescript
   processQueue({ error: null, token, queue });
   resolve(token);
   return customAxios(originalRequest);
   ```
2. **Prevent post-login execution when reloading**:
   If `location.reload()` is triggered in [`hooks/use-modal-session-expired.tsx`](file:///C:/Work/qcash-ui/hooks/use-modal-session-expired.tsx#L128), return early before reaching the retry block so in-flight requests do not race with document destruction.

### Code Plan: Prevent Post-Login Execution on Reload

#### Goal
When `globalThis.window.location.reload()` is triggered, immediately halt the execution of [`handleSignIn`](file:///C:/Work/qcash-ui/hooks/use-modal-session-expired.tsx#L194-L270) before it initiates the retry block (`retryPromises` and [`retryExceptionV2`](file:///C:/Work/qcash-ui/services/custom-axios.ts#L193-L223)).

#### Why this solves the issue
`window.location.reload()` does not synchronously terminate JavaScript execution. Without an early return, the rest of `handleSignIn` fires network retries while the browser is preparing to destroy the page. When those in-flight retries resolve, they trigger the provider's `.then()` callback and corrupt `localStorage["access-token"]` to `"[object Object]"` right before navigation.


This guarantees that whether a reload occurs or the page stays mounted, the provider's `.then((token) => ...)` always receives the string JWT token and never an Axios response object.
