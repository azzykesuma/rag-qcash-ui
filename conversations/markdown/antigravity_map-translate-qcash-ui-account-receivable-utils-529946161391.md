### Investigation Summary: `translateOptions` in `ReceivableHistoryChart`

In PR [#234 (Fix new translation)](https://internal-service.example.com/projects/NEWFE/repos/qcash-ui-account-receivable/pull-requests/234/diff#containers/receivable-overview/data/charts/receivable-history.tsx), the `<Select>` component in [receivable-history.tsx](file:///C:/Work/qcash-ui-account-receivable/containers/receivable-overview/data/charts/receivable-history.tsx#L168-L174) was changed:

```diff
- options={monthList}
- value={find(monthList, { value: activeMonth })}
+ options={translateOptions(monthList, t)}
+ value={translateOption(find(monthList, { value: activeMonth }), t)}
  formatOptionLabel={(option: Option<number>) => t(option.label)}
```

---

### 1. What is `translateOptions`?

Defined in [utils/map-translate.ts](file:///C:/Work/qcash-ui-account-receivable/utils/map-translate.ts#L80-L95):

```ts
export const translateOptions = <
  T extends { label?: any; options?: any[]; [key: string]: any },
>(
  options: T[] | undefined,
  t: (key: string) => string,
): T[] => {
  if (!options || !Array.isArray(options)) return [];
  return options.map((opt) => ({
    ...opt,
    label: opt?.label ? t(opt.label) : opt?.label,
    ...(Array.isArray(opt?.options)
      ? { options: translateOptions(opt.options, t) }
      : {}),
  }));
};
```

It iterates over option objects (and nested grouped options) and transforms each `option.label` using the translation function `t(label)`. `translateOption` does the same for a single selected `value` object.

---

### 2. Why was `translateOptions` introduced in PR #234?

Across several forms in the PR (such as `mandate-management/new`, `receivable-reports`, and `upload-mandate`), the author introduced `translateOptions` to address standard `react-select` (`qcash-global-component/select`) behavior:

1. **Search & Filter Matching**: `react-select` filters candidate items by matching user search input against `candidate.label`. If `options` keeps raw English labels (e.g. `"January"`) and only translates visually via `formatOptionLabel`, searching in Indonesian (e.g., `"Maret"`) or Chinese (e.g., `"一月"`) fails to match.
2. **Standardization for Selects without `formatOptionLabel`**: Many dropdowns throughout the app do not provide a custom `formatOptionLabel`. Pre-translating the `options` array standardizes label display across all dropdowns.
3. **Selected Value Consistency**: Passing `translateOption(selected, t)` keeps the `value` object's label in sync with the pre-translated items in `options`.

---

### 3. Issues Identified in `receivable-history.tsx`

While the intent was standardization, the implementation in [receivable-history.tsx](file:///C:/Work/qcash-ui-account-receivable/containers/receivable-overview/data/charts/receivable-history.tsx#L168-L174) introduces several problems:

#### A. Double Translation (Redundancy Bug)
Notice that `formatOptionLabel` was **not removed**:
```tsx
options={translateOptions(monthList, t)}
value={translateOption(find(monthList, { value: activeMonth }), t)}
formatOptionLabel={(option: Option<number>) => t(option.label)}
```
1. `translateOptions(monthList, t)` translates `"January"` → `"Januari"` (in `id`).
2. When `react-select` renders the menu item or value, it calls `formatOptionLabel(option)`.
3. `formatOptionLabel` receives the already-translated item and calls `t("Januari")`!
4. Because the translation dictionary key is `"January": "Januari"`, looking up `"Januari"` produces a dictionary miss. It only falls back to `"Januari"` because `t()` defaults to the input string when a key is not found.
5. In addition to being wasteful, this triggers missing-key warnings or could cause unintended translation collisions if an Indonesian word matches an English key elsewhere.

#### B. Missing Month Keys in Mandarin (`zh`)
In PR #234 commit [`89962901`](https://internal-service.example.com/projects/NEWFE/repos/qcash-ui-account-receivable/commits/89962901c001ed848990c139d3d5246609b1886d) ("remove common duplicates"), the author deleted `"January"`, `"February"`, etc., from `public/locales/zh/account-receivable.json`. They are also absent from `mapTranslate`. Consequently, `translateOptions` does not translate month names into Mandarin—they remain in English.

#### C. Unnecessary Re-allocations on Every Render
`monthList` is generated on every render:
```tsx
const monthList = generateMonthSelect();
```
Calling `translateOptions(monthList, t)` and `translateOption(...)` inside the JSX allocates new arrays and objects on every render cycle, bypassing React memoization on the remote `Select` micro-frontend component.

---

### 4. Recommendation

If you choose to use `translateOptions`, **remove `formatOptionLabel`** to prevent double translation, and memoize the options list:

```tsx
// Memoize translated month list
const monthOptions = React.useMemo(() => {
  return translateOptions(generateMonthSelect(), t);
}, [t]);

// Derive selected value directly from the already-translated options list
const selectedMonth = React.useMemo(() => {
  return find(monthOptions, { value: activeMonth }) ?? null;
}, [monthOptions, activeMonth]);

return (
  <Select
    name="filterReceivableHistory"
    onChange={handleChangeFilter}
    options={monthOptions}
    value={selectedMonth}
    // formatOptionLabel removed: options are already translated
  />
);
```

> [!TIP]
> Finding the active item from `monthOptions` directly (`find(monthOptions, { value: activeMonth })`) also eliminates the need for calling `translateOption(...)`.

Here is the breakdown of why the months are currently not translated:

---

### Root Cause Analysis

When `<Select>` renders:

```tsx
options={translateOptions(monthList, t)}
value={translateOption(find(monthList, { value: activeMonth }), t)}
formatOptionLabel={(option: Option<number>) => t(option.label)}
```

#### 1. What `monthList` produces
[`generateMonthSelect()`](file:///C:/Work/qcash-ui-account-receivable/utils/generate-month-select.ts#L3-L20) formats dates using `moment().month(i).format("MMMM")`. Because `moment.locale` is never set, it always produces raw English names:
`["January", "February", "March", "April", "May", "June", "July", "August", "September", "October", "November", "December"]`.

#### 2. What happens inside `t("January")`
In [`use-translate.ts`](file:///C:/Work/qcash-ui-account-receivable/hooks/use-translate.ts#L16-L29):
1. **`getMappedTranslationKey("January")`**:
   Checks [`utils/map-translate.ts`](file:///C:/Work/qcash-ui-account-receivable/utils/map-translate.ts). **None of the 12 months exist in `mapTranslate`**, so `lookupKey` stays `"January"`.
2. **`tAR("January")` & `LOCAL[lang]["January"]`**:
   - **Mandarin (`zh`)**: In commit `89962901` ("*remove common duplicates*"), all month keys (`"January": "一月"`, etc.) were **deleted** from [`public/locales/zh/account-receivable.json`](file:///C:/Work/qcash-ui-account-receivable/public/locales/zh/account-receivable.json).
   - **Indonesian (`id`)**: [`public/locales/id/account-receivable.json`](file:///C:/Work/qcash-ui-account-receivable/public/locales/id/account-receivable.json) **never had month keys** (they only exist in `public/locales/id/translation.json`, which `LOCAL` does not load).
3. **`tCommon("January")`**:
   The hook requests namespace `"common"`, but the local files on disk are named `translation.json` (there is no `common.json`), so `tCommon` has no loaded translations.
4. **Fallback**:
   Because `dict["January"]` is `undefined`, `t("January")` returns `"January"` (the untranslated key itself).

#### 3. Double translation in JSX
Even if `translateOptions` succeeded in translating `"January"` → `"Januari"`:
Because `formatOptionLabel={(option) => t(option.label)}` is still on the `<Select>`, it will immediately call `t("Januari")`. Since the dictionary key is `"January"`, `t("Januari")` would cause another lookup miss.

---

Either map the raw English month names directly in `mapTranslate`:

```ts

  ...
  // Months
  January: "data.month.january",
  February: "data.month.february",
  March: "data.month.march",
  April: "data.month.april",
  May: "data.month.may",
  June: "data.month.june",
  July: "data.month.july",
  August: "data.month.august",
  September: "data.month.september",
  October: "data.month.october",
  November: "data.month.november",
  December: "data.month.december",
};
```
And add the `data.month.*` keys into `public/locales/{en,id,zh}/account-receivable.json`:

* **`en`**: `"data.month.january": "January"`, etc.
* **`id`**: `"data.month.january": "Januari"`, etc.
* **`zh`**: `"data.month.january": "一月"`, etc.

*(Alternatively, restore raw month keys `"January": "Januari"` / `"January": "一月"` in `account-receivable.json`)*.
