## Turn 196: Assistant

**No, do NOT use `--frozen-lockfile` in this Dockerfile.**

### Why `--frozen-lockfile` will fail:
In the Dockerfile (lines 33–34), there is a `sed` step that modifies `yarn.lock` before installing:
```dockerfile
RUN sed -i 's|https://registry.npmjs.org|https://internal-service.example.com/repository/npm-group|g' yarn.lock && \
    sed -i 's|https://registry.yarnpkg.com|https://internal-service.example.com/repository/npm-group|g' yarn.lock
```
Because the registry URLs in `yarn.lock` have been rewritten to the internal Nexus URL, `yarn install --frozen-lockfile` will detect that `yarn.lock` was altered and fail the Docker build with:
```text
error Your lockfile needs to be updated, but yarn was run with `--frozen-lockfile`.
```

---

### What to use instead: `--pure-lockfile`

Use **`--pure-lockfile --network-timeout 600000`** (which is also the standard used in `qcash-ui-menu-management`, `qcash-ui-mpn`, etc.):

```dockerfile
RUN yarn install --pure-lockfile --network-timeout 600000
```

- **`--pure-lockfile`**: Tells Yarn to install strictly from the lockfile without generating or writing a new lockfile, but **without** failing the build due to the `sed` URL rewrites.
- **`--network-timeout 600000`**: Prevents build failures caused by slow responses or transient timeouts when pulling packages from the internal Nexus registry.
