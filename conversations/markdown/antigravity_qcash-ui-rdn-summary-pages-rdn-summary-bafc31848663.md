No, the error is not simply because the test is excluded, but rather due to two main factors:

---

### 1. SonarQube Has Not Re-Scanned Yet
SonarQube does not update locally in real-time. It reflects the last scan run by the **Bamboo CI pipeline on `dev`** (PR #34). The test coverage fixes we just made in [`tools/test/__tests__/pages/app.test.tsx`](file:///D:/work/qcash-ui-rdn-summary/tools/test/__tests__/pages/app.test.tsx) need to be **committed and pushed** (or merged via PR) so Bamboo can run the test suite, generate `tools/coverage/lcov.info`, and send the new coverage report to SonarQube.

---

### 2. How `sonar.exclusions=**/test/**` Works
In [`sonar-project.properties`](file:///D:/work/qcash-ui-rdn-summary/sonar-project.properties#L11):
- `sonar.exclusions=..., **/test/**` tells SonarQube **not** to treat test files as production code (so test files aren't analyzed for production bugs/smells or expected to have unit tests themselves).
- This is standard practice and **does not prevent SonarQube from reading coverage** for source files (`pages/_app.tsx`) from `tools/coverage/lcov.info`.

---

### 3. Why `pages/_app.tsx` Failed Coverage on `dev`
In the previous PR (#34):
- [`pages/_app.tsx`](file:///D:/work/qcash-ui-rdn-summary/pages/_app.tsx) was modified to introduce `useRouter()` and pass `router` to `AuthProvider`.
- SonarQube flagged the newly modified lines as **0% covered** because the existing unit test didn't assert or cover the `useRouter`, custom layout, locale synchronization, and federation initialization branches.

---

### Options to Resolve for CI / Quality Gate

#### Option A: Full Unit Test Coverage (Already Implemented Locally)
We have updated [`tools/test/__tests__/pages/app.test.tsx`](file:///D:/work/qcash-ui-rdn-summary/tools/test/__tests__/pages/app.test.tsx) to cover 100% of the branches, hooks, router passing, and remotes in `_app.tsx`. Once pushed, Jest will record full coverage for `_app.tsx` in `lcov.info`.

#### Option B: Add `sonar.coverage.exclusions` (Alternative Pattern)
If you prefer not to track coverage on Next.js boilerplate/entry files (like in other QCash MFEs), you can add `sonar.coverage.exclusions` to [`sonar-project.properties`](file:///D:/work/qcash-ui-rdn-summary/sonar-project.properties):
```properties
sonar.coverage.exclusions=pages/_app.tsx,pages/_document.tsx,ni18n.config.ts
```

---

### Next Step
Would you like to proceed with committing and pushing the updated test suite (Option A), or would you also like to add `sonar.coverage.exclusions` for `_app.tsx` (Option B)?

### Cause & Solution

1. **Why the failure occurred**:
   - In [`pages/rdn-summary/index.tsx`](file:///D:/work/qcash-ui-rdn-summary/pages/rdn-summary/index.tsx#L10-L21), `init(...)` and `loadRemote(...)` are called at the **module level** (outside the React component).
   - Because `beforeEach` runs `jest.clearAllMocks()`, the mock invocation recorded during the initial module load was cleared before that specific test case ran.

2. **The Fix**:
   - Wrapped the module load in [`jest.isolateModules()`](file:///D:/work/qcash-ui-rdn-summary/tools/test/__tests__/pages/rdn-summary.test.tsx#L156-L158) inside the test:
     ```tsx
     it("initializes module federation remotes when window is defined", () => {
       jest.isolateModules(() => {
         require("@/pages/rdn-summary/index");
       });

       expect(init).toHaveBeenCalledWith({
         name: "qcash-ui-rdn-summary",
         remotes: [
           {
             name: "qcash-global-component",
             entry: `${config.baseFederation}/global-component/_next/static/chunks/remoteEntry.js`,
           },
         ],
       });
       expect(loadRemote).toHaveBeenCalledWith("qcash-global-component/globals");
     });
     ```
