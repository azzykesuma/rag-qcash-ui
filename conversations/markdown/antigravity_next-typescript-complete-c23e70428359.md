## Turn 116: Assistant

Penjelasan mengenai review comment tersebut ([Comment #166179](https://internal-service.example.com/projects/NEWFE/repos/qcash-ui-group-management/pull-requests/219/overview?commentId=166179)):

---

### 1. Apa yang Dikomentari oleh Cikal?
Komentar tersebut tertuju secara spesifik pada penambahan **`GlobalStoreProvider`** di dalam `pages/_app.tsx`:
```tsx
// Sebelum diperbaiki:
<AuthProvider apiUrl={config.baseUrl as string} router={router}>
  <GlobalStoreProvider>{getLayout(<Component {...pageProps} />)}</GlobalStoreProvider>
</AuthProvider>
```
Cikal menuliskan *"gak usah ditambahin kl emang gak pake"* karena **`GlobalStoreProvider`** sebelumnya memang tidak ada di baseline repo ini dan tidak dibutuhkan untuk root layout `_app.tsx`.

---

### 2. Mengapa `<AuthProvider>` Tetap Dibutuhkan di `_app.tsx`?
Semua repo MFE di Q-Cash menerapkan pola **Centralized Auth Guard**:
1. **Mode Standalone (Local Dev / Direct Ingress)**:
   - Saat repo dijalankan mandiri (`yarn dev` / port lokal), `_app.tsx` berjalan sebagai root aplikasi.
   - `<AuthProvider router={router}>` di `_app.tsx` bertugas menginisialisasi sesi autentikasi dan memvalidasi rute secara otomatis sehingga kita bisa **menghapus semua boilerplate `guard()` manual** di setiap `pages/*.tsx`.
2. **Mode Micro-Frontend (Remote via Host/Shell)**:
   - Karena `@bri/addons-auth-provider` diset sebagai **`singleton: true`** di `next.config.js`, saat halaman di-load sebagai remote oleh Host (misal `qcash-ui-dashboard`), seluruh komponen di dalam `group-management` otomatis berbagi React Context yang sama dari Host.

---

### 3. Kesimpulan & Perbaikan yang Sudah Dilakukan
- **`<AuthProvider>`**: **Tetap dipakai** di `_app.tsx` untuk sentralisasi auth guard.
- **`<GlobalStoreProvider>`**: **Dihapus** dari `_app.tsx` sesuai masukan Cikal.

```tsx
// Hasil akhir di pages/_app.tsx:
<AuthProvider apiUrl={config.baseUrl as string} router={router}>
  {getLayout(<Component {...pageProps} />)}
</AuthProvider>
```
